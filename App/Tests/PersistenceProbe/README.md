# Production persistence restart checks

This macOS 27 executable tests StudyPersistence using disposable stores and synthetic account data. It is not linked into the app. No mode accesses a live account, system Keychain or saved preferences.

`mainboard run usagi-test-native-v1-values` (standalone `native-v1-values`) independently builds the original writer's domain/storage modules from `writer-sources.zip` and its original checkpoint reader from `baseline-reader.zip`. It does not resolve the current `Shared` package or require Git history/network access. The new wrapper supplies the original module names, Swift 6 settings and resources. Both fresh processes restore the exact canonical 38-record fixture twice; source hashing checks all 67 original paths/bytes, and two negative controls refuse changed bytes or an extra source before store opening. Hashes of both archives and the canonical baseline/writer/manifest are checked before and after. The wrapper and extracted build/results stay separate from the normal probe and shipping targets. This preserves historical decoders for future work; it does not implement a V2 migration. See the [checkpoint and remaining gates](../../../Docs/Implementation/2026-10-21-frozen-ios-and-review-focus.md#independent-historical-value-decoders).

The separate `mainboard run usagi-test-storage-space` parent task (or standalone `native-store-space`) creates a bounded APFS image using Apple's current `diskutil image` CLI. `probe-application-space` requires a frozen fixture copy on that named image, then uses `write-application-space`, `commit-application-space` and `verify-application-space` children. It checks real `ENOSPC` before mutation and before commit, exact rollback after space returns, retry with the original revision, all 38 records across two fresh reopens, and unchanged original/retained images and selector. The dirty-commit callback exists only in this probe. No SQL mutation, production fault hook or live store is involved. Compact typed receipts/logs survive successful ejection and backing-image cleanup. See the [recorded scope and evidence](../../../Docs/Implementation/2026-10-21-frozen-ios-and-review-focus.md#actual-apfs-disk-full-save-and-recovery).

From the monorepo root, `mainboard run --as-is usagi-test-persistence` builds with two compiler jobs and runs ten phases within a 600-second deadline: `write` → `read-attempts`, `write-catalog` → `read-catalog`, `read-native-baseline`, `probe-native-upgrade`, `probe-application-opening`, `probe-application-payload-corruption`, `probe-application-metadata-corruption` and `probe-application-adoption-corruption`. The original pairs use separate processes and preserve completed sessions, uncertain answers, exact attempted notes, account isolation and catalog metadata. The simpler `read` mode accepts stores from earlier probe binaries. The catalog reader also verifies that an older unbound import receipt does not select a writer.

The DEBUG-only baseline reader and upgrade experiment share the pinned fixture at `Fixtures/native-v0-186c1cc3/study.store`, written by `186c1cc3`. They validate its provenance and copy it before any persistence API opens a store. The complete baseline covers 38 records, ten model types, fifteen Codable attributes and two accounts, including global/unbound receipts. Never regenerate this fixture to make a migration pass.

`probe-native-upgrade` names the unchanged schema as version 1.0.0 and uses the public Core Data store-replacement API on disposable clones. It requires exact schema/domain equality in fresh processes, preserves a committed WAL-only material edit, and proves a named-schema save survives reopening. It also records the limits of a read-only source option: writable clones can gain/change SHM and WAL bookkeeping; a filesystem-protected journal-free source refuses with SQLite error 8, while the protected WAL generation remains byte/name-exact. Candidate permissions change only on its disposable copy. The original fixture's complete file names and SHA-256 hashes must remain unchanged.

The experiment's `verify-native-upgrade`, `seed-native-upgrade-wal` and `write-native-upgrade` child commands require its marked temporary fixture. The WAL writer deliberately exits 86 after a real committed save; the parent requires that exit and checks the saved state. The primary phase exits 0 only after its assertions pass. This is macOS 27 test evidence: its schema still references current model classes and has no migration stages. It does not implement production capture/selection, freeze a historical V1, change stored fields, prove external-data copying, run inside iOS or close G7. No production model, container or bootstrap code is changed.

The same binary has handoff checkpoints. With a **fresh** disposable path, run these in order, each through `mainboard run --as-is mainboard proc timeout 60 apps/usagiunagi/.build/Probe/debug/NativePersistenceProbe <mode> <absolute-store-path>`:

| Mode | Expected exit | Boundary |
| --- | --- | --- |
| `import-handoff` | 86 | Import and verified prepared binding committed; credential not saved |
| `save-handoff` | 86 | Synthetic credential file persisted; writer not activated |
| `activate-handoff` | 86 | Native writer choice committed; abrupt exit before first preference write |
| `edit-handoff` | 0 | Change native work, consume the old answer and simulate logout |
| `read-handoff` | 0 | Reopen offline without reading retired data or resurrecting old work |

Exit 86 is deliberate `_exit(86)`, skipping SwiftData/Swift teardown. The latter processes cannot verify identity online, so successful recovery requires the durable binding and preference snapshot. The activation phase uses a disposable defaults subclass to exit before hydration; resumed phases verify original preferences and the absence of a token preference. The workflow requires the exact checkpoint message as well as exit 86. Credentials use a separate disposable file; that exercises commit ordering, not Apple's Keychain internals. Do not run a new writer over an existing account store.

With a second fresh path, `rollback-handoff` must exit 86 after a malformed pending answer rolled back. `verify-rollback-handoff` then exits 0 only if a fresh process finds no partial catalog, account, snapshot, receipt binding, pending work or credential. The existing shared GitHub Actions job includes all phases through Mainboard. Timeouts, crashes with another exit code and unexpectedly normal exits fail the gate.

For native schema upgrades, build the writer from the exact earlier committed source in a disposable package, then run the current `read-catalog` against that store. The handoff checkpoint validates `2e77f23` → current, including the optional receipt attribute. Earlier catalog upgrades are historical evidence in Docs/Validation.

These checks do not activate the iOS writer cutover or prove physical/signed-device behavior, actual Keychain failures, power-loss durability or complete app parity. Actual SQLite schemas 9–15 and unchanged source bytes are covered separately by hosted Swift Testing. CloudKit remains disabled for this local store.

`probe-application-opening` exercises the production generation opener on marked disposable copies: base/WAL adoption, lease refusal, committed answer/note survival across abrupt exit and fresh-process reopens. Two additional base/WAL cases call the public answer operation and exit 87 inside ModelContext.willSave, after checking the complete dirty session/outbox/mistake transaction. Two fresh processes must restore the exact prepared 38-record state. A third process retries the same reading and preserves the original wrong-meaning penalty in exactly one pending answer; two more reopens restore all 39 records. The original/retained images and selector remain unchanged. The shared save observer exists only in this executable; the app has no fault hook. See [pre-commit interruption evidence](../../../Docs/Implementation/2026-10-21-frozen-ios-and-review-focus.md#completed-review-pre-commit-interruption).

`probe-application-payload-corruption` runs 27 scenarios: two truncated payloads, fifteen wrong-typed JSON fields, nine required NULL mutations and one populated review-issue control with exact 38-record comparison. Each exercised negative case must throw safely (exit 74); signals or returned owners fail. SQL constraint rejections are explicitly unexercised. Original/retained/selector bytes, generation membership and selected DB/WAL must stay unchanged; selected SHM bookkeeping may change. Children have time/output/free-space bounds, and only passed marked copies are removed after assertions. Both primary commands are in the existing Actions persistence lane; publication and a hosted run remain pending.

The opening phase also kills two separate ordinary/WAL-source children when a complete `selected` selection file first becomes visible. The child calls the production opener and then holds its owner without further account access or cleanup. The parent polls for at most ten seconds, requires actual SIGKILL termination and the exact observed selector bytes, then runs two exact-state readers, lease refusal, the first answer/note write and two further reopens. This tests a visible publication boundary before the first app write, not an instruction inside atomic rename/fsync, mid-copy interruption or power loss. The fifteen-second child hold is bounded independently; timeout cleanup kills only that child. No production hook is added. See [publication scope](../../../Docs/Implementation/2026-10-21-frozen-ios-and-review-focus.md#published-selection-process-interruption).

`probe-application-payload-validation` separately records the public Core Data binary-projection experiment. Its successful raw preflight is not a substitute for the actual production-opener command. These commands require the same pinned fixture argument as `probe-native-upgrade` and a command-scoped Xcode 27 `DEVELOPER_DIR`; run them through root Mainboard with a hard timeout. Never run child commands or SQL corruption against an unmarked store. The broader failure matrix and physical iOS adoption remain open.

`probe-application-metadata-corruption` separately checks six selected-generation cases: an exact 38-record control, missing metadata row, malformed metadata property list, removed model-version hashes, missing model-cache row and malformed model cache. Each negative case changes exactly one row with readback and requires a caught opener error, no signal and the same preservation rules as the payload matrix. The fixed matrix stops on its first failure and retains that image. Successful marked case copies are removed only after assertions; typed outcomes and logs remain. This proves safe refusal on Mac, not first-adoption corruption, iOS failure handling or recovery from arbitrary damage.

`probe-application-adoption-corruption` mutates a marked unselected source before any production open. It checks an intact control, malformed required account payload, missing model cache and malformed metadata, each in two fresh processes. Failed inputs must remain preparing rather than selected, with source/retained bytes and every earlier preparation artifact unchanged across retry. New candidate/work paths are allowed. The intact control must reopen with exact 38-record state and stable selection; only selected SHM bookkeeping may change. A fixed 512-path/32-MiB snapshot bound supplements existing child/capacity limits. All eight attempts must pass before any successful image is removed. This is Mac first-adoption evidence, not interruption, iOS corruption or full G7 acceptance.

The catalog reader also verifies old account bytes decode with no `catalogRefreshID`. Automatic-read acceptance builds the writer from exact commit `70414fb6` in a disposable archive, then reads that store with the current binary. The optional marker belongs to the existing Codable account value; no SwiftData column is added. See [current evidence](../../../Docs/Validation/2026-10-20-automatic-catalog-reads.json).
