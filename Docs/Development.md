# Development and GitHub Actions

Use Xcode 27.0 / Swift 6.4; Mainboard selects the toolchain. The obsolete Swift 5.1 swiftenv pin and unused Clang-format config were retired. Use the stable iOS 27.0 runtime. Open `App/UsagiUnagi.xcworkspace`, select the `UsagiUnagi` scheme and choose an iPhone, iPad or **My Mac** destination. My Mac is a native macOS build; Catalyst and the iPad compatibility destination are disabled. `Tsurukame` remains the internal app target/module for existing callers and data compatibility. `Tsurukame` also retains the hosted unit-test scheme.

## Native compiler policy

The Xcode project's Debug and Release configurations now own one inherited Swift 6 language setting and `SWIFT_TREAT_WARNINGS_AS_ERRORS = YES`. Targets no longer duplicate the language setting, and the UI-test runner no longer selects Swift 5 on iOS versus Swift 6 on Mac. Its teardown directly terminates the fixture application rather than capturing the non-Sendable XCTestCase through a one-use wrapper. No assertions or fixture boundaries change.

All nine Shared production/support/test targets use SwiftPM's native [`.treatAllWarnings(as: .error)`](https://developer.apple.com/documentation/packagedescription/swiftsetting/treatallwarnings(as:_:)), supported since SwiftPM 6.2. Existing concurrency/default-isolation settings retain their scopes. This covers Swift compiler warnings; it does not suppress or promote Interface Builder/metadata tool diagnostics. The archived historical writer, separate probe manifests and external package configurations are not rewritten. Mainboard continues to execute native builds and diagnostics without a second warning checker.

SwiftLint's existing `unneeded_synthesized_initializer` rule now signals redundant struct memberwise/default constructors through the same strict Mainboard/Actions lint path. Automatic correction remains disabled; caller visibility, state seeding, bindings and validation still require review. The standalone manifest declares Xcode in `on.osx.env`, preserving an explicit shell/CI `DEVELOPER_DIR` and otherwise using `/Applications/Xcode.app/Contents/Developer`. All four native lint tools enter that environment through `mainboard run --locked --no-install`; they do not require a manual export, install tools or change global Xcode selection. Command Line Tools alone lack the required SwiftParser/SourceKit host libraries.

## Mainboard owns execution

From this app checkout, `mainboard run --locked setup` installs the pinned correctness tool,
`mainboard run --locked lint` checks the full repository without changing files,
`mainboard run --locked test` runs the shared Mac Swift Testing suites, and
`mainboard run --locked build` compiles the unsigned iOS simulator Debug app. `typecheck`
delegates to that same native build. Hosted app/UI, iOS shared, watch and recovery checks
remain separate required tasks; `test` alone does not establish full acceptance.
The complete lint command intentionally reports formatting in protected owner edits rather
than excluding them or claiming a green result. CI's gradually adopted style scope is explicit.

Generic Apple patterns live in Mainboard: native arguments, committed package resolution, process-tree timeout, fresh result bundles, diagnostics, test verdicts and simulator URL delivery. There is no app `Tools` folder or custom CI shell driver. Schemes, test filters, fixtures and resource generation remain app-specific.

The optional cloud transport now has one [private display-preferences configuration](PrivateICloud.md). Both platform entitlements and app metadata use `USAGI_ICLOUD_CONTAINER_IDENTIFIER`; signing/container registration is still required before live sync. Existing hosted fixtures never create this owner. Shared tests use disposable local-only sidecars and defaults, so the regular Mainboard tasks require no iCloud login or network access. No cloud-schema initialization hook runs at startup.

Fresh-process retry preserves all abandoned artifacts, restores the complete expected state and commits a verified pending note before two more reopens. No production fault hook is added. The same task runs in the shared Actions lane; it is not an iPhone/Data Protection/power-loss or actual mid-copy interruption test. See the [note](Implementation/2026-10-21-frozen-ios-and-review-focus.md#actual-apfs-disk-full-save-and-recovery), [review](Implementation/2026-10-21-frozen-ios-and-review-focus.md#completed-review-disk-full-transaction) and [WAL matrix](Implementation/2026-10-21-frozen-ios-and-review-focus.md#committed-wal-disk-full-matrix) checkpoints.
