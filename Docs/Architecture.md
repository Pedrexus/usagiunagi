# One shared codebase

The [migration specification](Migration.md) owns the current target, phase dependencies and acceptance contracts; [TASKS](TASKS.md) separates accepted checkpoints from tested prototypes with open adoption gates. Later sections here retain historical decisions and their original evidence, not a claim that every draft or platform gate is complete.

`Shared/Package.swift` is the common implementation for iPhone, iPad and Mac. Its package name remains StudyKit; the public modules are StudyCore, StudyPersistence, StudySpeech and StudyUI. Swift 6.4, Swift 6 language mode, Sendable domain values, actor-owned persistence and MainActor SwiftUI are already enabled there. One multiplatform target in `App/UsagiUnagi.xcodeproj` consumes that exact package. `App/UsagiUnagiApp.swift` is the common SwiftUI entry point, with native Mac and iOS/iPadOS destinations.

| Boundary | Shared responsibility | Remaining platform work |
| --- | --- | --- |
| Domain | Grading, kana conversion, sessions, lessons, preferences, curriculum and statistics | Remove legacy protobuf adapters after the iOS writer handoff |
| Data | URLSession API client, SwiftData store, durable outbox, recovery and audio downloads | All three shipping platforms use the shared SwiftData store; old SQL remains for import/test compatibility |
| Presentation | SwiftUI review, lesson, catalog, details, settings, Home and statistics components | Shared production scene on every platform; retire the remaining isolated legacy test host and narrow platform bridges after acceptance |
| Speech | Apple capture and confirmed transcript flow | Physical microphone, model availability, interruptions and latency validation |
| Platform | Small capability and layout adaptations | Lifecycle, windows, notifications, badge, audio session and Keychain configuration |

`StudyAppModel` in `Shared/Sources/StudyUI/Application` owns observable account, restore, refresh and explicit-send state in Swift 6. Its typed `StudyCredentialStore` preserves the existing Mac Keychain namespace and cache path; account-model tests cover transitions, failed credential operations, pending-work preservation and cancellation.

`StudyRootView` in that same module owns the native Home/Practice/Stats shell and one value-based `NavigationStack` with a typed destination path. Study screens open above the tabs; Back pauses the session and Home offers Resume. Home reads use SwiftUI task cancellation and a minute timeline. `StudyAvailability` is the common native Home/session selector; practice uses `StudySession` without assignment/statistics/review-upload effects. `ReviewScreen` is presentation content: native, legacy iOS and sheet hosts each supply one navigation stack. `App/Application/StudyAppAssembly.swift` composes one app-owned service value retained by `StudyApplicationOwner` in SwiftUI State. It supplies the same model, media owners and preferences to every route. Synthetic accounts and server responses live in `App/AppStoreScreenshots/NativeStudyFixture.swift`, behind DEBUG; a single factory chooses that environment. The native and temporary iOS hosts share the font fixture definition. No native feature screen belongs in assembly.

Native reviews now reuse `ReviewScreen`'s settings, end and wrap-up toolbar on every platform. Ask later remains a secondary action; Back still pauses the durable session. The compact card puts the prompt/level/stage beside its Japanese text so the keyboard cannot squeeze those labels below the card. Results reuse `SessionSummaryView`, with Done in the navigation bar and sync guidance in the list footer. Summary accuracy counts completed subjects and their first missed meaning/reading; retries do not become extra subjects. Kanji show primary readings, vocabulary keeps alternate readings, and the existing old-meaning preference applies to radicals. Missed entries reopen native details; image radicals use the shared SVG cache.

The OS launch surface uses [Apple's `UILaunchScreen` dictionary](https://developer.apple.com/documentation/bundleresources/information-property-list/uilaunchscreen). It precedes SwiftUI execution; no app launch view controller is needed. The unused beige launch storyboard, generated accessor and build references are deleted. Other storyboards still belong to the legacy acceptance host or retained watch UI.

Shipping iPhone, iPad and Mac now consume the shared root/model/store. `StudyApplicationOwner` coalesces bootstrap before exposing services. iOS chooses the previously verified schema 9–15 credential/preference/media handoff or durably marks a fresh native installation; neither path opens the retired writer. An activated selection cannot fall back to stale legacy credentials after logout. Errors preserve the original source and offer an explicit retry. Separate-process abrupt-exit checks cover the handoff, rollback and fresh-native selection. The old iOS coordinator is selected only by the legacy DEBUG screenshot test launch, which must be ported before its source/dependency deletion. Signed-device Keychain upgrades remain a separate acceptance gate.

Put business behavior and screens in Shared. Keep `#if os(...)` at the narrow platform capability edges; prefer layout and availability adaptation inside views. There is one SwiftUI app entry point; the iOS legacy coordinator remains only as an isolated DEBUG test host. `App/Platform` contains temporary capability bridges; platform configuration stays in `App/Configuration`. The remaining watch target is a companion, not another phone/Mac app.

## Native application cutover, October 20

`StudyApplicationWindow` queues incoming routes during bootstrap and owns per-window state. Its scene-keyed SwiftUI task starts the shared automatic worker after an active scene has awaited the app-owned preparation; a phase transition cannot leave sync unstarted. `StudyAppModel.refresh()` reads without rewriting the Keychain. Background refresh uses SwiftUI `backgroundTask(.appRefresh)` and the system scheduler, with cancellation checks before an explicit shared synchronization; it does not start a second automatic worker. Background delivery/expiration still require real-device acceptance.

Native settings now include the original timing display and iOS keyboard preference, runtime API endpoint validation, shared avatar cache, consistent SQLite diagnostic export and confirmed logout. The same typed core computes level-up timing from cached server SRS intervals. Saved Work observes committed store changes so counts reflect automatic upload. A narrow `UIViewRepresentable` owns Japanese input-language, marked-text and caret behavior on iOS; responder changes are deferred outside SwiftUI view updates to prevent a hosting-graph cycle. Mac uses the native SwiftUI field. Physical Japanese IME acceptance is still open. Original lesson/review search and Siri activity identities are configured once in shared UI and donated with SwiftUI `userActivity`; the temporary UIKit host calls that same metadata implementation. Prediction eligibility stays at the iOS capability edge. Modern AppIntents discovery remains separate work.

The sections below also preserve migration decisions from earlier checkpoints. Statements describing native iOS composition as pending predate this cutover; remaining release gates are maintained in [TASKS](TASKS.md) and its current validation receipt.

## Native lesson navigation acceptance

The native lesson parent owns picker selection through a binding, preserving it when the teaching/quiz child leaves the hierarchy. The picker retains a local fallback only for its temporary legacy caller. A paused manual quiz exposes its existing subject selection and validates it against the frozen durable session; it cannot replace another session or credit unfinished work. Automatic batches use the page's Back control to return to the current parent tab. On iOS the enclosing navigation Back gesture is disabled while teaching/quiz paging is active, so a horizontal lesson swipe cannot pop the study route.

Existing lesson/detail and cold/warm-link acceptance now use native services and the production scene. The canonical cold test covers both custom URL schemes; the warm test proves an incoming subject waits during an open review/settings sheet, then returns to its unchanged draft after explicit Open. `LessonFlowFixture` and its completion state are removed, while remaining legacy callers stay intact pending their equivalent native checks.

## Supported sign-in

`StudySignInFields` supplies the same token entry, submission, errors and reactivation guidance to the standalone iOS form and native Mac account screen. `StudySignIn` owns the authentication task; closing its form cancels that operation and clears transient input. A request identity also rejects late results from noncooperative services. A cancelled parent propagates to the owned operation through Swift's cancellation handler. Native connection errors remain typed until the common UI presents them. App-owned cache synchronization may still finish for another scene; a cancelled form cannot commit credentials or switch the visible account.

The developer-only password/token scraper and its live probes are removed after the existing token form supplied the supported alternative. [WaniKani's authentication contract](https://docs.api.wanikani.com/20170710/#authentication) requires third-party apps to use personal API tokens, without collecting account passwords. The app opens WaniKani's token settings for the user; it does not log into the website or create tokens on the user's behalf. Previously saved API tokens remain usable. Reconnecting legacy account context is displayed read-only; it is not another credential.

Legacy iOS reauthentication now captures its cache owner before validating a replacement token. Before writing either archived credential field, it checks cancellation, the unchanged service/client and cached identity, then matches the fetched account's username and signup timestamp when retained by that archive. A mismatch keeps the original token and saved work. Level/subscription progress does not define identity. Old protobuf caches do not retain WaniKani's stable account UUID: archives missing a signup date can only match the username; renamed accounts fail closed. This is a protection for the existing writer, not proof of the future credential/import handoff. The shared SwiftData store retains its independent UUID-bound checks.

Both hosts validate tokens through `WaniKaniClient.account`. Its official default remains HTTPS. Explicit developer test-server configuration is retained, with request/pagination/response scope bound to the selected scheme, host, port and base path; URLs with embedded credentials, query or fragments are rejected as base configurations. GET-user hibernation messages retain the website reactivation path. Other rejected calls, especially writes, retain their original unauthorized classification and single-attempt behavior.

The remaining legacy API transport now uses Foundation URLSession directly inside its existing PromiseKit contract. PMKFoundation, the scraper-only regular-expression helpers and form encoder are removed. JSON body logging is also retired; JSON wire encoding remains. Swift 5/protobuf/PromiseKit persist only for the active iOS writer and its callers. The shared form does not migrate the iOS UserDefaults token archive into the native Keychain namespace; that recoverable credential ordering still belongs to the cold writer handoff.

Those destinations no longer push individual UIKit controllers. `DeveloperSettingsContent` retains only the original archived endpoint, service and diagnostic/cache capabilities; its actual form remains the shared `DeveloperSettingsView`. `SettingsViewController` still connects the legacy scene/services, account notifications and outer Back action until native root adoption. The separate Fonts, Offline Audio and Developer Options controller classes are removed.

`ReviewSettingsSheet` owns the same quick-settings/media navigation on both hosts. Back from Fonts returns to quick settings; Done from a media page returns directly to the review. The iOS boundary refreshes the existing question presentation after either Done or interactive dismissal, preserving the draft and applying font changes even when an iPad sheet does not trigger the presenter's appearance callback. Font/download owners outlive the sheet. Native review queue/session controls stay in main Settings, matching the original quick-settings scope; hiding them from the in-session sheet does not remove those settings or rewrite saved session choices.

The remaining UIKit presentation/input and lifecycle boundaries are still explicit. This cleanup does not select the native iOS writer, select production archive/credential handoff, add native Mac diagnostic capabilities or claim physical IME/notification/watch acceptance. The active iOS database and its diagnostic export remain available.

## Preference handoff audit

The cold handoff now captures the effective original preferences without opening a writer or invoking mutating settings getters. The following table separates preservation implemented in the handoff engine from production integration still required:

| Existing source | Native owner | Required preservation |
| --- | --- | --- |
| Review, appearance, order/cap and leech archives in `Settings` | `native.reviewPreferences` | Decode the existing enum codes/scalars and map every field through the shared types. Missing legacy SRS indicator defaults to **none**, while the native type defaults to **name**; legacy minimize-penalty defaults to **true**, native to **false**. Do not replace those effective old choices with native defaults. |
| Lesson and subject archives | `native.lessonPreferences`, `native.subjectPreferences` | Preserve the values already mapped by the legacy preference adapters, including order, access/exclusion and graph/display choices. |
| `selectedFonts`, `offlineAudio`, `offlineAudioCellular`, `offlineAudioVoiceActors` | `native.selectedFonts`, the three native audio keys and media libraries | Convert archived sets/scalars to the native storage types. Preserve offline files: the old libraries use Documents/fonts and Documents/audio; native assembly uses Application Support/TsurukameNative/fonts and audio. The handoff now selects the original Documents directories and compatible filenames, retaining files in place. The native Mac default stays in Application Support; production iOS composition must pass the receipt’s media layout. |
| The three archived notification choices | `native.notificationsAllReviews`, `native.notificationsBadging`, `native.notificationSounds` | Decode actual booleans, then compose native scheduling/badge/companion ownership. Copying archive bytes into these boolean keys is not a migration. |
| `gravatarCustomEmail`, with `userEmailAddress` fallback | Native avatar settings/header | Preserve the effective avatar without discarding an explicit new override or reusing another account's fallback email. The native header now reads an account-bound fallback when no custom address is set. |
| `subjectCatalogueViewShowAnswers` | `catalog.showAnswers` | Preserve the existing catalog answer-visibility choice; this key does not use the native prefix. |
| `autoSwitchKeyboard`, `showMinutesForNextLevelUpReview`, `apiBaseUrl` | Native capability/settings work still missing | Supply equivalent keyboard selection, level-up timing presentation and configured native service/diagnostic behavior before retiring their old controls; they cannot simply be omitted from a preference export. |

`Settings` getters can write archives when a key is absent or contains an unarchived value, and its enum getters force an unknown raw value. The cold reader validates existing scalars, enum codes and sets from one immutable defaults snapshot using Foundation’s [allowed-class secure unarchiver](https://developer.apple.com/documentation/foundation/nskeyedunarchiver/unarchivedobject(ofclasses:from:)-3h32t). It preserves missing legacy defaults, archived and raw source values, and includes the typed preference snapshot in the durable import receipt. After activation, every bootstrap hydrates only absent native keys; saved native choices and subsequent edits win. A crash between activation and hydration resumes from that receipt without reading retired data, credentials or the network. Malformed existing native data remains available for recovery and blocks bootstrap; it never authorizes the old writer. Older activated receipts with no snapshot retain their original writer choice. Media uses compatible existing directories rather than copying files. The native service factory can receive the captured endpoint; native keyboard selection, minute timing display, diagnostic/account controls and production scene composition remain open. Credential storage remains a separate Keychain handoff; account tokens must not enter preference or diagnostic exports. The legacy-only full-answer onboarding flag is not a grading setting.

## Shared review policy

Both hosts use `FullReviewSettingsContent` for review order/cap, session choices, display, marking, audio and leech threshold. The iOS wrapper retains only its Japanese-keyboard capability/alert and legacy level-up display preference. The form uses the existing system typography, grouped sections, SF Symbols and WaniKani palette; no new visual theme is introduced. Quick settings continue to omit queue/session controls. The unused legacy enum-picker wrapper is retired after the last form caller moves to shared controls.

`StudyReviewPolicy` selects new scheduled queues: shuffle ties, apply one of the nine original orders, then cap. Sort keys are projected once; alternating low/high selection is linear after sorting. Home continues to count all due reviews. Lessons and extra study do not use the scheduled-review cap; new practice queues shuffle. Resuming native saved work returns its original revision, selected items and options before consulting new policy values. The legacy engine retains its existing live session-option reads.

`ReviewPreferencesAdapter` preserves the Objective-C order raw values and all original archived keys. Its fieldwise updates preserve unrelated settings edits; turning Anki off retains the old task archive and clears combined mode. Native preferences use the same fieldwise merge policy. Shared leech scoring uses Double precision and checks meaning alone for radicals and kana-only vocabulary; hidden statistics and zero streaks cannot qualify. The old iOS filter incorrectly required an unused reading streak for those meaning-only subjects.

Native full downloads now fetch and validate [WaniKani SRS system definitions](https://docs.api.wanikani.com/20170710/#spaced-repetition-systems), normalize the documented units to seconds and cache the typed definitions with account state. Longest relative wait uses the subject's system/stage interval, with the original hourly time boundary. A missing/invalid response cannot publish a partial refresh. Old account bytes decode without metadata, and older typed refresh clients cannot erase an existing cache. No SwiftData schema change or review upload is involved.

The one retained interval table is explicitly compatibility data: original protobuf subjects lack system IDs and use their original accelerated-level rule; older native caches without definitions may use known default system IDs. Unknown IDs require a refresh instead of guessing an interval. Legacy `SRSStage.duration` delegates to this same table; it no longer owns another copy. This does not establish calibrated forecasts or support arbitrary future changes to the session engine's stage semantics.

## Native confirmed-work synchronization

`StudyAutomaticSync` is one app-owned worker shared by native windows. It observes committed store changes, account changes through Swift's [Observations sequence](https://developer.apple.com/videos/play/wwdc2025/245/), and Apple's [NWPathMonitor async sequence](https://developer.apple.com/documentation/network/nwpathmonitor). Foreground, connection restoration and successful explicit account/recovery actions wake it. A local commit is not a network acknowledgement: safe, never-attempted work uploads automatically; uncertain, rejected or changed records still require recovery. The service does not reset the current question, session revision or typed draft.

`StudySynchronization.uploadSavedWork` sends without downloading the complete catalog. Existing manual Saved work sync still sends and downloads, while ordinary refresh is a read. All three operations share one account/credential-fenced lane; a read queued after upload-only still performs its requested download. Acknowledged assignments come from their current records, preserving pending exclusions and legacy references. This fixes the regression in which a successful upload deleted the pending row and then exposed the old downloaded stage/due date again. Older imported profile metadata never replaces a newer verified snapshot. A fresh identity-checked account response can atomically update the account and all credential snapshots; its complete profile decoding is shared with full downloads. Saved-at remains the full-read timestamp. Home/reminders observe a local data revision; audio catalog access also reacts to a verified profile change. These metadata changes are published even if a later write reply is lost.

Network/server failures back off from fifteen seconds to five minutes; stored rate-limit deadlines are never shortened. Known authorization/account failures suspend automatic attempts until an explicit wake instead of looping on their own attempt-marker transactions. A lost reply retains durable uncertainty and produces recovery guidance immediately. Vacation updates the local gate, still permits notes and retains review/lesson work. Disconnect drains the underlying shared lane; reconnect does not turn an uncertain old write into a fresh submission.

`WaniKaniService` is the typed six-operation repository boundary; `WaniKaniClient` remains the production URLSession implementation with its response, origin and single-attempt write validation. The native UI fixture now supplies a typed, stateful in-memory service instead of raw JSON replies or a GET-only transport that would make simulated uploads fail. It simulates controlled assignment advancement and acknowledgements, not WaniKani's real SRS algorithm. Every UI exercise remains synthetic; no live account or credential is used.

This closes normal native sending, not the whole storage handoff. iOS still runs its current SQLite writer, which already sends its own confirmed work; the native worker is compiled/tested there but becomes the app owner only with shared-root adoption. Foreground account/catalog cadence and post-study reads now use this same owner; incremental HTTP reads remain future work. The existing full Refresh action remains available. Full-account/signed-device network interruption, companion/background ownership and production scene adoption remain open; the bootstrap engine has separate schema 9–15 and process-crash coverage. See [automatic-sync validation](Validation/2026-10-20-automatic-native-sync.json).

## Incoming links

`StudyCore.StudyLink` is the common typed parser for custom `usagiunagi` and legacy `tsurukame` links, plus HTTPS links on the existing `tsurukame.app` domain. It accepts path and authority custom-scheme forms, decodes path components without splitting encoded subject text, and rejects unknown routes, credentials, invalid IDs and other HTTPS hosts. `StudyActivity` retains the two original shortcut activity identifiers. Both app configurations register the schemes and activity types. No new domain is invented; real universal-link delivery still depends on signing and the site's association file and has not been accepted here. Full AppIntents/shortcut discovery and donation parity remain open.

The shared root queues signed-out requests, coalesces consecutive duplicates and fences asynchronous resolution to the current account and first request. Switching an existing account clears its old queue. Home/Stats can open directly; study, practice, catalog and root sheets require an explicit Open. A native settings sheet blocks interaction with the queued control behind it, verified by an actual pointer click. The same saved study session takes precedence over a request for different work, with an inline explanation; it is never overwritten. Subject links read accessible records through the store actor. Wrap-up invokes the existing session mutation only after an active review is explicitly selected, without grading or uploading an answer. Link feedback is separate from sync errors.

The root uses [SwiftUI's existing-scene preferences](https://developer.apple.com/documentation/swiftui/view/handlesexternalevents(preferring:allowing:)) and [active appearance](https://developer.apple.com/documentation/swiftui/environmentvalues/appearsactive) to route to an existing Mac window. A failing acceptance run first demonstrated an unintended second window; the view preference fixed delivery without an app-specific AppKit bridge. The legacy iOS coordinator consumes the same parser and queues valid links until sign-in, retaining its existing writer/controller actions. This is shared routing behavior; it does not switch iOS persistence ownership.

## Unfinished review input

`NativeReviewView` uses SwiftUI `SceneStorage` for the unfinished typed answer, validation feedback and answering/retry phase. The key includes the account ID and the store's current saved-session revision. Reopening that same question restores the text and retry presentation; another account, an advanced/discarded session or a different stored revision cannot receive that draft. Anki presentation is reconstructed from the existing persisted decision and does not consume a typed draft.

This is lightweight UI continuity within a scene. [Apple documents](https://developer.apple.com/documentation/swiftui/scenestorage) that scene storage is separate per scene, has no guaranteed persistence schedule and is destroyed when the scene is explicitly destroyed. The app does not promise unsubmitted text survives closing a Mac window or destroying an iPad scene. Grades, queues and uploads remain owned by the existing revision-checked SwiftData transaction; no schema, query, account credential, grading or sync changes are involved.

## Subject edits and vocabulary exclusion

Hiding the control does not remove an existing exclusion. The lesson form no longer needs a platform-injected vocabulary section.

## Shared pronunciation and offline audio

`StudyAudioLibrary` owns selected voices, download policy, the current account's accessible audio catalog and one playback engine. Both hosts use `AudioLibraryView`/`OfflineAudioView`; subject details and reviews consume the same player. iOS retains its three archived preferences and Documents/audio/a{subject}-{voice}.mp3 cache contract. Native Mac uses primitive UserDefaults values and Application Support/TsurukameNative/audio. Disabling downloads retains files; explicit deletion stops playback/downloads, disables downloading and retains voice choices. Priority remains current level, earlier levels in reverse order, then the next accessible level, with at most four active transfers per level.

Native catalog reads omit hidden and subscription-locked subjects and reject another account. Changing/disconnecting the account cancels active transfers and playback without deleting the cache. Repeated reads of an unchanged catalog do not restart downloads. Playback rotates voices, prefers the chosen cached recording, then any other cached voice, and only then streams an HTTPS URL. Decode failures and loading can be recovered/cancelled through shared inline controls. The cache downloader validates response status, media type and nonempty bytes; the playback engine validates actual media decoding.

`AppleStudyAudioPlayback` uses [AVFoundation's native Observation support](https://developer.apple.com/documentation/avfoundation/observing-playback-state-in-swiftui). It enables the global Observation setting before creating playback objects and creates each player lazily on play. Async observations and an item-specific completion stream replace manual KVO and UIKit alerts. Completion/failure/cancellation are fenced to that player; an old notification cannot stop a replacement. iOS releases the audio session before voice capture starts. Voice sheets hold a shared playback lease across windows and release it after capture cleanup, or after a finished transcript is confirmed for grading.

## Cold-start handoff boundary

Current iOS startup creates `TKMServices` in `AppDelegate`, but does not open `LocalCachingClient` there. `LegacyStudyWindow.task` later creates `LegacyStudyCoordinator`, which opens that writer. Background fetch returns `.noData` while the client is absent. The production iOS scene still follows this path: native writer selection has not been activated in the app.

`StudyLegacyBootstrap` now implements the recoverable handoff needed at this boundary. It must be owned once by the app and run before creating either account writer/background service. Initial preparation verifies the legacy token through the read-only `WaniKaniAccountReader` capability, matches the username and retained signup date, and checks that the source/token did not change during verification. It imports one complete schema 9–15 export, applies fresh verified access/vacation metadata, then binds the existing import receipt to its source ID, verified account and credential fingerprint. Raw credentials are never stored in that receipt. Existing direct imports without this binding require fresh verification.

The prepared receipt commits before saving a credential. Bootstrap refuses to overwrite another credential and reads the saved value back before committing activation. A crash before saving, after saving or after activation can resume from the durable state; an exact prepared source can finish offline. A scene cancellation does not interrupt the app-owned handoff. Import remains idempotent, so interruption between importing and binding cannot resurrect consumed uploads. Changed source data or a missing prepared snapshot fails closed. Malformed imports roll back without a credential or writer choice.

Activation is a one-way **writer** decision, independent of later account selection. Once activated, bootstrap never reads the retired source, network or credential to choose a writer again. Logout, a rotated token, a removed old snapshot or changed native work cannot reopen the old writer or re-import its stale queue. The receipt's account ID identifies the original import, not the currently signed-in account. The original database/token archive is retained; no migration path calls `clearAllDataAndClose()` or automatically falls back to legacy after an error.

The existing persistence executable checks abrupt process exits before credential saving, after its synthetic save, after activation and after a failed import rolled back. Fresh processes verify offline recovery, retained exact uncertain payloads and no resurrection after simulated logout. Hosted Swift Testing executes bootstrap against actual disposable SQLite schemas 9–15 and checks unchanged source bytes and reopen behavior. An exact previous-commit writer/current-reader check validates adding the optional handoff attribute to older native stores. These tests use synthetic credentials; they do not prove real Keychain failures, signed-device upgrades, power-loss durability or a production iOS cutover.

Production iOS now gates its native scene through this bootstrap before opening features. It exposes recoverable failures, honors the durable native choice and preserves original files. Normal startup does not construct the old writer. The remaining legacy host exists for unported acceptance; retire it only after those flows and the native recent-mistake cloud/source handoff are verified. See [handoff validation](Validation/2026-10-20-native-bootstrap.json) and [current tasks](TASKS.md).
