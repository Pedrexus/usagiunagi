# One shared codebase

The primary product and design target is the iPhone/iOS study experience. iPad and native Mac use the same SwiftUI screens, navigation, state and services, with mostly automatic adaptations. Prefer available space, text size and real capabilities over device names or operating-system checks. Improve the iPhone flow first; validate that its shared adaptations also work elsewhere.

The current implementation uses one SwiftUI app, `App/UsagiUnagiApp.swift`, for iPhone, iPad and native Mac. `App/UsagiUnagi.xcodeproj` has one multiplatform app scheme. Catalyst and the iPad compatibility destination are disabled. The main app, shared package and retained watch targets use Swift 6 language mode with the Xcode 27 / Swift 6.4 toolchain.

One hosted `AppTests` target and folder now serve both SDKs, using native SDK selection and the same executable-path formula: `$(BUILT_PRODUCTS_DIR)/Tsurukame.app/$(BUNDLE_EXECUTABLE_FOLDER_PATH)/Tsurukame`. Repository tests now seed native SwiftData values directly. The SQLite/protobuf importer, archive-reader sources and protobuf dependency are removed. UIKit input and WatchConnectivity assertions remain scoped to iOS because those adapters have no native Mac counterpart. Mainboard's `test-app-ios` and `test-app-mac` run this common non-UI target with the explicit fixture marker; rendered acceptance remains a separate gate. Frozen persistence fixtures and the archived historical writer retain their canonical paths under `App/Tests/PersistenceProbe`. The current probe retains its reader/comparer and no longer builds the retired importer or baseline writer.

Automated validation has passed within the scopes recorded in [current tasks](TASKS.md); rendered usability and signed-device acceptance remain unfinished. The owner requested production changes first, then comparison with the original Tsurukame, then tests. Historical receipts apply only to their recorded sources. [The migration specification](Migration.md) defines storage and account-safety contracts.

## Native initialization and synthesis

Avatar URL generation and its image-cache actor now belong to the app alongside the avatar view. Neither is a persisted model or used by the storage package. Their existing tests belong to the shared hosted app target. The URL helper explicitly remains nonisolated when compiled with the app's default MainActor setting; the cache retains its own actor isolation. This is a source-ownership change, with the existing HTTP cache, image bounds, cancellation and account-clear behavior preserved.

The font catalog and observable download owner also live in the app. Settings and review views use the same owner; preferences retain their existing string-based file selections. Value types and download errors explicitly remain nonisolated, while the catalog and download owner keep their existing MainActor isolation. Download callback staging remains synchronous before its actor hop because URLSession removes the temporary file when the callback returns. Weak captures here preserve cancellation on owner release and are not removed merely to shorten the implementation.

Pronunciation playback, download ownership and their defaults adapter belong to the app as well. The shared package retains `StudyAudioOptions` and `StudyAudioCatalog` unchanged: historical preferences reference the former, and the SwiftData actor returns the latter. Moving their source into `StudyAudioCatalog.swift` does not change their module or declarations. The app owns the existing voice-input lease that stops pronunciation before capture and prevents competing playback until capture releases it. The AVAudioSession iOS boundary remains necessary; native Mac playback still uses the same AVPlayer implementation.

Use Swift's synthesized struct initializers and stored-property defaults for internal values and views. Six forwarding/default constructors are removed from `StudyCard`, `StoredReviewPreferences`, `StudySourcesView`, `UpcomingReviewsView` and its `Count`/`Hour` values. Their only callers are inside the app module, so these helpers no longer expose unnecessary public APIs. A stored `@ViewBuilder` content property supplies StudyCard's generated builder initializer. These changes remove nineteen physical production lines without changing the view bodies, stored preferences or data models.

After moving UI into the app, eight more initializers use native synthesis, removing 59 production lines. Five structs use memberwise initialization (including stored `@ViewBuilder` content); three observable classes use the default initializer because every property already has an initial value. Classes still do not get memberwise initialization. The app root initializer is internal because its default inbox no longer needs a public constructor. Initializers that seed view state, compute metrics or wire services remain explicit. No macro dependency or persisted-model change is involved.

The [Swift 6.4 initialization guide](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/initialization/) documents memberwise struct initialization, default arguments from property defaults and the default initializer when every stored property has a default. This is native language synthesis; no memberwise macro package or new abstraction is required. Codable, Equatable and Hashable synthesis already cover many existing domain values where their requirements hold.

The follow-up removes another 24 forwarding initializers from settings, account fields, tabs, summary, recovery and catalog controls used only inside StudyUI. Bindings/Bindable inputs and stored ViewBuilder content use native synthesis; optional configuration defaults live on the view properties. Private State/Environment ownership remains private. ReviewSettingsPanel keeps its state-seeding initializer, and lesson/catalog/voice/service initializers retain their bounds, derived values or injected owners. The unused standalone sign-in view is removed; the active root Account form still owns cancellation. Its surviving fields now live in `Account/StudySignInFields.swift`. The two passes remove 194 physical production lines overall. SwiftLint's existing `unneeded_synthesized_initializer` rule is enabled through Mainboard; its finite syntax check complements caller/visibility review rather than proving that every initializer can be deleted.

Keep explicit initializers at genuine boundaries. [Synthesized memberwise initializers are at most internal](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/accesscontrol/), so public domain values constructed by other modules retain their public initializers. Classes, including SwiftData models, do not gain struct memberwise initialization. Validation, dependent values, persistent identities, injected services and historical decoding defaults retain their existing initialization logic. Property defaults do not by themselves make missing JSON keys decode with those defaults. Do not erase those responsibilities to reduce line counts.

## Ownership and storage

Networking uses Foundation's async `URLSession.data(for:delegate:)`, `URLRequest` and `JSONDecoder`, with fixed-category `async let` downloads and explicit `@concurrent` boundaries for transport/decoding. The shared package has no external dependencies. SwiftUI `.task(id:)` owns view-scoped reads and `.refreshable` owns pull-to-refresh; durable shared synchronization retains its application lifetime. Replacing that owner with a disappearing view's task would change upload/cancellation behavior. No HTTP client framework, generic request/repository layer or OpenAPI build generator is needed. Apple's current [URLSession guidance](https://developer.apple.com/documentation/foundation/urlsession), [task API](https://developer.apple.com/documentation/swiftui/view/task(id:name:priority:file:line:_:)) and [Swift concurrency model](https://docs.swift.org/latest/documentation/diagnostics/nonisolated-nonsending-by-default/) support these responsibilities.

The API downloader reuses the actor's saved subject values and server collection watermark. `updated_after` results merge by subject ID into a complete catalog before the existing full-replacement transaction; hidden updates remain explicit. Endpoint/revision/access-level scope, a saved row count and a weekly complete read bound cache reuse. An empty delta keeps the previous watermark; pagination retains the first page's server timestamp so later changes are read again. Cursors live in the existing account dictionary and commit with content. Other collections remain complete reads. This changes neither V1's stored declarations nor the queue/receipt owner. The retired Parquet/catalog-export pipeline is unnecessary; normal diagnostic sharing and offline preview remain.

`StudyApplicationOwner`, held in SwiftUI state, coalesces startup before publishing services. `StudyAppAssembly` supplies the same account model, persistence actor, font/audio libraries, notification owner, subject/lesson settings, image caches and voice factory to every route. Windows share services rather than constructing another writer.

`StudyAppModel` owns account restoration, refresh, cancellation and observable account state. `StudyStore` commits decisions, completed submissions, notes and outbox changes atomically. Pausing a screen preserves its durable session; scene storage holds only transient answer drafts. The network layer distinguishes unsent work, attempted requests with uncertain replies, acknowledged work and explicit recovery. It never silently replays an uncertain answer or clears saved work on an error.

Foreground sync monitoring starts from the same active-scene task on iPhone, iPad and Mac. Its small Equatable identity contains the scene phase and whether services are prepared, so a successful startup Retry changes the identity even if the scene remains active. Shared preparation survives a canceled waiting view; the app-owned sync worker remains idempotent and outlives individual windows after starting. Initial Mac startup no longer starts a duplicate worker from preparation. Explicit iOS background refresh still calls the existing background owner directly. Actual Retry-to-activation delivery remains a rendered acceptance gate; the identity follows Apple's [task restart contract](https://developer.apple.com/documentation/swiftui/view/task(id:name:priority:file:line:_:)).

Window groups share `defaultSize(width: 1120, height: 800)`, an initial window preference rather than a minimum content frame. Apple documents [system clamping and restored window sizes](https://developer.apple.com/documentation/swiftui/scene/defaultsize(width:height:)). The remaining Mac scene guard encloses only [default launch behavior](https://developer.apple.com/documentation/swiftui/scene/defaultlaunchbehavior(_:)) and [disabled restoration](https://developer.apple.com/documentation/swiftui/scenerestorationbehavior/disabled), which the selected public SDK marks unavailable on iOS. Those API boundaries do not select different feature layouts.

Synchronization and publication belong to the app. A canceled waiting view still receives cancellation, but the committed snapshot/profile publish together first; account/credential generation changes continue to fence that publication. Sign-in and reauthentication retain caller cancellation so a dismissed form cannot commit credentials.

Shared fetches belong to internal synchronous methods on the concrete SwiftData models: `CatalogRecord`, `AssignmentRecord`, `AccountRecord` and `MaterialRecord`. Their extensions live beside the current feature code, outside frozen V1 declarations. The store actor passes its existing `ModelContext`, for example `MaterialRecord.fetch(in: modelContext, accountID: accountID, subjectID: subjectID)`. Transactions, account/revision checks and network orchestration remain on that actor; public entry points return Sendable domain values. Prefer these direct model methods and native SwiftData APIs. Introduce another layer only for a concrete responsibility that existing models or the actor cannot express clearly.

iOS cold import reads the original database through SQLite3 in a read-only transaction, verifies stable account identity and persists an idempotent handoff before activating native services. Archived preference metadata/decoding is independent of the removed Settings UI and does not write defaults while reading. Original databases, media and credential compatibility are preserved. Regular application writes use SwiftData; the old FMDB writer and raw SQL diagnostic export have no production caller and are retired.

Production startup uses the owner-approved generation opener. It preserves a read-only source image, validates a separate candidate against physical schema metadata and complete values, durably selects that candidate, and retains its actor/lease for service ownership. The ten V1 model declarations preserve their original identities. Handoff values use typed equality so unordered preference Sets cannot falsely reject an equivalent store; session/catalog order stays significant. Disposable frozen base/WAL adoption, exact records, lease refusal, writes and abrupt-process reopens pass on Mac. Mainboard's eight-phase iPhone task verifies graceful and abrupt reopening after a completed graded review and new note, plus abrupt interruption during verification and candidate opening before selection. The completed-review cases restore all 39 records, exact DB/WAL bytes, session/revision, wrong-answer penalty, timestamp and pending upload; repeated session reads neither requeue work nor replay success feedback. Each opening-interruption consumer checks every pre-exit artifact byte before opening, then recovers all 38 frozen records with a fresh candidate, preserving the original, retained and abandoned images across two actor reopens. Deliberate runner failures remain explicit checked receipts. Mid-copy/final-publication interruption, stopping before an answer transaction commits, physical failures and wider G7 combinations remain open. Historical nested decoders need independent freezing before a V2/property change. See the [implementation checkpoint](Implementation/2026-10-20-native-store-opening.md), [iPhone interruption evidence](Implementation/2026-10-21-frozen-ios-and-review-focus.md#abrupt-interruption-before-iphone-store-selection) and [migration specification](Migration.md).

Existing store images receive a read-only Core Data payload preflight before SwiftData property decoding. Public binary expression projections and the exact frozen model hashes let the existing generation owner validate all fifteen Codable fields without triggering SwiftData's fatal transformed-value decoder. Normal queries/writes remain on SwiftData models and the store actor. Selected-store matrices safely refuse 26 actual malformed-payload cases and five metadata/cache cases on Mac and iPhone Simulator; iPhone cases repeat each refusal and preserve selected DB/WAL as well as original/retained/selection data. Native metadata errors may remain Cocoa/Foundation errors; lease/cancellation failures cannot stand in for refusal in the tests. Three damaged first-adoption inputs also refuse twice in fresh Mac processes, preserving original/retained images and all abandoned preparation artifacts; exact-state controls pass. Broader interruption/device/performance acceptance remains open. This adds no per-launch clone or storage service. See the [safeguard](Implementation/2026-10-21-adaptive-validation.md) and [expanded evidence](Implementation/2026-10-21-frozen-ios-and-review-focus.md).

The existing opener also passes real task cancellation at observed preparation, prepared-candidate and selected-store open events on Mac/iPhone. Preparation/candidate work stays unselected, an existing selection stays byte-exact, original/retained data survives and a new caller can acquire the lease and restore the complete two-account state. Retry preserves abandoned candidate files and chooses a fresh candidate. The test observes public Core Data notifications and cancels a Swift task; no fault hook or second persistence owner is added. These same-process storage-open events do not cover mid-copy cancellation, final synchronization/selection publication races or process/power interruption.

Failed lock creation preserves the native POSIX error instead of reporting every failure as `EIO`. Actual simulator permissions test both refusal attempts and complete recovery after restoring directory access, covering lease, selector, preparation and candidate-directory boundaries. Every prior artifact remains intact except the explicitly advancing preparing selector. These are POSIX permission checks, not physical iOS Data Protection or disk-full acceptance; see the [permission checkpoint](Implementation/2026-10-21-frozen-ios-and-review-focus.md#unwritable-adoption-and-native-permission-errors).

Directory containment compares normalized filesystem paths for root equality. Foundation URL values can differ only in their trailing directory hint while naming the same path; comparing those URL values rejected real Application Support startup during preparation. Recursive creation still requires the same root or a slash-delimited descendant and validates actual directory/symlink types. The fix adds no OS branch, platform utility or schema change. The cross-process test uses only the existing fixture marker, a test-only scheme and Mainboard's bounded native commands; no helper process or new switch ships in the app.

Startup comparisons now retain a typed `StudyGenerationSnapshot` instead of encoding a second opaque contents blob. Header/identity/attribute checks, canonical field bytes, full-record equality and typed handoff Set equality are preserved. Only activation digests encode the aggregate value. Adoption reuses the snapshot already verified against its source; there is no external candidate owner before publication. Existing selected-store receipts are unchanged and remain readable. The ten persisted V1 models are untouched. See the [startup comparison evidence](Implementation/2026-10-21-adaptive-validation.md#typed-startup-comparison-and-synthetic-scale).

## Study experience

Avoid parallel phone/tablet/desktop feature flows, an `isMac` utility layer or a generic platform capability framework. A view should only need an OS branch when an actual API or supported service is unavailable; keep that boundary narrow and explain it below. Do not hide a removable condition inside a helper or sacrifice Japanese input, accessibility, keyboard behavior or offline study merely to reduce a count.

The remaining shared-UI OS conditions configure Japanese input, iOS keyboard traits, audio interruption, notification authorization/system Settings and activity prediction. They do not choose separate layouts or navigation flows. Keep these checks beside their unavailable APIs; replacing them with generic flags would add indirection without making the experience adapt better. Review new screens first at iPhone portrait width, then with larger text, the keyboard present, a short landscape viewport and freely resized windows.

Review layout defaults to stacked iPhone portrait content. A short, wide study viewport can put the question beside one answer column, retaining the input subtree and its focus owner. Window/keyboard resizing must not trigger an extra focus command. Form sheets, search and title display use the same declarations on all three platforms. Native lesson reordering uses the SwiftUI 27 container rather than separate desktop buttons and mobile edit mode.

Review control rows use one private content-fitting helper: try their full ideal horizontal size, then a vertically growing stack. This responds to narrow windows, longer labels and text scaling without an OS/device flag or an accessibility-category cutoff. This follows Apple's [`ViewThatFits`](https://developer.apple.com/documentation/swiftui/viewthatfits) sizing contract. The lesson-selection footer also tries its count and Start button at their natural widths before stacking. Its horizontal form preserves leading count/trailing action placement. Selection, loading/error state and the asynchronous lesson-start operation belong to the enclosing picker; changing the layout does not create another feature owner. Keep stateful input out of duplicated fitting alternatives. Use `AnyLayout` when an existing stateful subtree must keep its identity across a layout change.

One permanent review scroll surface contains progress, the question, answers and revealed information. Its content fills the offered height when it fits and grows when text/controls need more space; scrolling does not dismiss the answer keyboard. Embedded subject details return their existing content into that surface, while standalone details keep their own scroll owner. Lesson tiles use adaptive minimum widths and heights, with large-text meaning labels and selection actions allowed to grow. The picker and teaching strip retain full catalog subjects so image-only radicals render through the existing cached SVG view. Lesson quizzes keep system fonts; custom review-font settings remain available for reviews/practice.

Coverage's menu filters use their natural width in `ViewThatFits`, stacking when a horizontal row does not fit. Revealed Anki uses the existing menu's primary action and Return to open assessment; one shared action body keeps grading, deferring, exclusion and synonyms available without assigning default credit. The Japanese input adapter explicitly preserves locked text on Cut and routes Backspace to retry; editable deletion stays with the system field. These are local controls, not a new platform or input framework. Actual-field tests pass; rendered adaptive/menu/keyboard acceptance remains open.

`StudyRootView` owns one typed navigation stack and the Home, Practice and Statistics destinations. Review, lesson, catalog and settings behavior lives in shared views. WaniKani subject colors, system text styles, SF Symbols and native glass controls remain the visual basis. Layout adapts to available space; platform conditions belong at capability boundaries.

Home's Search and Settings use the root's native primary-action toolbar group. Saved work and Refresh use automatic toolbar placement. The account header devotes its width to the avatar, username and level; it no longer measures or styles a second action bar. Actions and accessibility identifiers stay shared, with no device or OS layout conditions. Native placement and overflow still require compact/wide and large-text on-screen acceptance.

Main and watch app icons compile directly from the shared `Resources/UsagiUnagi.icon`. SF Symbols and Swift color definitions own the current screen styling. Font previews retain their separate shared-package resource catalog. Reviews and extra study use the same grader/session engine. Continuing after an incorrect answer can advance without revealing it. Ending early retains the completed-item summary while discarding unfinished session work. The old DEBUG UIKit host, duplicate controllers, fifteen iOS storyboards, generated navigation/assets wrappers, FMDB and associated dependency integration are retired. The three previously excluded owner-edited remnants are also removed after preserving their exact source and patch in ignored local reports. Database/preference/JSON snapshot import, Haneke cache adoption, username-based iCloud mistake exchange and ClockKit migration are retired. ## Developer workflow

Mainboard owns dependency restoration, bounded Xcode operations, results/diagnostics, formatting, lint, Swift syntax rules and per-file source inventory. There is no app-local build driver. `mainboard rules swift-inventory` reports physical/nonblank lines, source classifications, imports, platform conditions and placed migration signals; it does not infer target membership or safe deletion. CocoaPods/SwiftGen integration is removed; native Swift packages retain committed resolution.

Mainboard's read-only `apple bundle` command now owns built-product inspection: native metadata, requested localized names, relative resource exclusions and complete all-architecture undefined-symbol/library output with file hashes. The app manifest owns its policy and four Release build/audit tasks; local parent tasks and the dedicated Actions matrix delegate to those declarations. The committed empty `mb.lock` permits locked restoration without adding Python/Conda package dependencies. Reports describe supplied products, independently of signing, rendering, exact source provenance or optimized-out static packages. No temporary audit script is needed for current Release checks.

Apple execution now retains readable JSON diagnostics beside each exact result bundle, including failed native runs. `analyze swift-compare` compares saved source inventories with category changes separate from byte changes. These reuse Mainboard's typed reports and atomic generated-file writer; routine edits use direct patches and existing formatters. Neither feature authenticates a supplied inventory or proves the compiler's exact source inputs. See the [workflow checkpoint](Implementation/2026-10-20-mainboard-reports.md).

Synthetic services remain in DEBUG-only acceptance fixtures, isolated from real credentials/cloud/permissions.
