A build alone does not close a behavior task. Keep a task open if any required acceptance item remains.

## Scope and decisions

- iOS/iPadOS 27+, native macOS 27+, app-owned code moving to Swift and SwiftUI. Preserve existing study behavior unless a change is explicitly agreed.
- Basic native Apple controls, system fonts and SF Symbols; WaniKani subject identities and clear information hierarchy. No return to the rejected animal mascot; the current icon is an abstract layered 兔鰻 mark.
- 兔鰻 for Japanese/Chinese name localizations; usagiunagi elsewhere. Repository renamed to Pedrexus/usagiunagi. Store metadata is prepared, not published.
- iPhone Duo-specific work is **deferred by the user**, not a completion requirement now. Generic adaptive phone/iPad/Mac layouts remain required.
- Keep narrow keyboard/SVG bridges until equivalent behavior is verified. Inform the user before any feature must be disabled. Do not silently remove functionality to achieve a language/framework percentage.
- Prefer Apple frameworks and less app-owned plumbing: SwiftData for local persistence, URLSession with Swift concurrency for networking, SwiftUI observation for presentation, and AppStorage for ordinary preferences. WaniKani remains the authority for study progress; do not mirror the upload queue through CloudKit.
- Keep credentials, installed-app data and durable review queues intact. App-owned Swift does not mean rewriting operating-system libraries or all build tools.

### Serialized upload and response-validation checkpoint (2026-10-17)

- Added a shared Swift 6 `UploadCoordinator`. The iOS app uses one process-wide upload lane for immediate review/lesson completion, note/synonym edits and background sync. Jobs queue subject keys, reload the latest durable payload when their turn starts, skip already-acknowledged rows, and acknowledge only the exact bytes sent. A failed job does not poison later independent jobs. SQLite remains the durable store.
- A synchronous lifetime fence invalidates existing upload jobs before database reset/logout and prevents late upload acknowledgements from touching the reset store. This covers the uploader, not all legacy download callbacks or every multi-scene/account-switch path. Existing in-flight server requests may still finish; this is not a remote rollback.
- Fixed material writes bypassing HTTP validation. Both POST and PUT now use the normal status/JSON/rate-limit path, require a valid study-material resource for the requested subject, and refuse a lookup for a different subject. Error and malformed responses keep notes/synonyms pending. The old success tests had empty response bodies; they now use the documented resource response, and each API test clears request stubs.
- Removed blanket deletion of progress on HTTP 422. The [WaniKani error contract](https://docs.api.wanikani.com/20170710/#errors) does not make 422 proof of successful prior submission. Pending reviews are retained and the error propagates. **Reconciliation remains open:** a rejected review can still block its upload batch and the following legacy download phase until resolved. Implement assignment-based reconciliation and a durable conflict record/UI before closing OUTBOX; do not silently discard the review or claim exactly-once submission.
- The [current review endpoint documentation](https://docs.api.wanikani.com/20170710/#create-a-review) says reviews are no longer persisted and returned IDs are always zero. Reconciliation must not depend on fetching a historical review record. Assignment state can show that the server advanced, but cannot alone prove which device performed an ambiguous review.
