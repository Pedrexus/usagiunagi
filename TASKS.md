# usagiunagi task tracker

This is the persistent source of truth for the modernization. Update it in every implementation checkpoint, including evidence and remaining limitations. The active Codex goal is to carry the requested work through completion, not merely produce a plan. Work is reviewed in [PR #1](https://github.com/Pedrexus/usagiunagi/pull/1).

Status: **done** = implemented and verified for the stated scope; **in progress** = being changed; **open** = still required; **needs external validation** = implementation cannot establish the remaining behavior without a device/account. A build alone does not close a behavior task. Keep a task open if any required acceptance item remains.

## Scope and decisions

- iOS/iPadOS 27+, native macOS 27+, app-owned code moving to Swift and SwiftUI. Preserve existing study behavior unless a change is explicitly agreed.
- Basic native Apple controls, system fonts and SF Symbols; WaniKani subject identities and clear information hierarchy. No return to the rejected animal mascot; the current icon is an abstract layered 兔鰻 mark.
- 兔鰻 for Japanese/Chinese name localizations; usagiunagi elsewhere. Repository renamed to Pedrexus/usagiunagi. Store metadata is prepared, not published.
- iPhone Duo-specific work is **deferred by the user**, not a completion requirement now. Generic adaptive phone/iPad/Mac layouts remain required.
- Keep narrow keyboard/SVG bridges until equivalent behavior is verified. Inform the user before any feature must be disabled. Do not silently remove functionality to achieve a language/framework percentage.
- Keep credentials, installed-app data and durable review queues intact. App-owned Swift does not mean rewriting operating-system libraries or all build tools.

### Serialized upload and response-validation checkpoint (2026-10-17)

- Added a shared Swift 6 `UploadCoordinator`. The iOS app uses one process-wide upload lane for immediate review/lesson completion, note/synonym edits and background sync. Jobs queue subject keys, reload the latest durable payload when their turn starts, skip already-acknowledged rows, and acknowledge only the exact bytes sent. A failed job does not poison later independent jobs. SQLite remains the durable store.
- A synchronous lifetime fence invalidates existing upload jobs before database reset/logout and prevents late upload acknowledgements from touching the reset store. This covers the uploader, not all legacy download callbacks or every multi-scene/account-switch path. Existing in-flight server requests may still finish; this is not a remote rollback.
- Fixed material writes bypassing HTTP validation. Both POST and PUT now use the normal status/JSON/rate-limit path, require a valid study-material resource for the requested subject, and refuse a lookup for a different subject. Error and malformed responses keep notes/synonyms pending. The old success tests had empty response bodies; they now use the documented resource response, and each API test clears request stubs.
- Removed blanket deletion of progress on HTTP 422. The [WaniKani error contract](https://docs.api.wanikani.com/20170710/#errors) does not make 422 proof of successful prior submission. Pending reviews are retained and the error propagates. **Reconciliation remains open:** a rejected review can still block its upload batch and the following legacy download phase until resolved. Implement assignment-based reconciliation and a durable conflict record/UI before closing OUTBOX; do not silently discard the review or claim exactly-once submission.
- The [current review endpoint documentation](https://docs.api.wanikani.com/20170710/#create-a-review) says reviews are no longer persisted and returned IDs are always zero. Reconciliation must not depend on fetching a historical review record. Assignment state can show that the server advanced, but cannot alone prove which device performed an ambiguous review.
- Validation: 51 shared Swift Testing functions (45 core, 6 speech) pass, including four new concurrency/lifetime cases. 55 iOS unit/integration tests pass, including a real SQLite test that changes notes/synonyms during a gated upload and verifies the latest payload is sent once and local notes remain. 25 mocked API-client tests pass, covering POST/PUT HTTP 401/422/429/500/503, malformed/empty successes, mismatched resource identity, and valid creation/update. Native Mac compilation passes. These are controlled tests; no real-account uploads are claimed.
- OUTBOX/SYNC remain open for the reconciliation and lifecycle work above, storage migration/rollback, server resets/vacations and explicit backoff. Durable review-session resume and Mac review parity still depend on those boundaries.

### Download merge prerequisite (2026-10-17)

- Found and fixed a mismatch between fresh-payload uploads and legacy full refresh: refresh previously deleted the study-material rows that hold pending edits before the queued upload reloaded them. Full refresh now resets only download cursors. Each complete endpoint response replaces its cache and advances its cursor within the same transaction; failed downloads retain the prior offline snapshot.
- Additive schema 14/15 migrations record local revisions for notes and subject progress without changing protobuf bytes. Material/assignment requests capture revisions before downloading; their merge protects newer local changes even when an upload has already acknowledged them. Changing a note back to its previous bytes is covered. Material replacement/merge also preserves pending local bytes, including edits made while a download is in flight. Assignment merges preserve pending local SRS progress and keep pending subjects out of review queues even when the server changes an assignment ID. Full assignment replacement retains current mistake timestamps and prunes only obsolete, non-pending progress. Removed the old finalizer that could overwrite a newer mistake timestamp with a pre-sync copy.
- Download merges, sync phase transitions, finalization and error logging now respect the repository lifetime invalidated by reset/logout. A late response cannot write through that expired lifetime. Multi-scene identity/reauthentication, cancellation of actual network tasks and all account transitions remain to be validated; this is not a blanket account-isolation claim. Burned practice now tolerates a locally completed item without a downloaded assignment.
- Validation: 67 iOS unit/integration tests pass, including twelve new SQLite cases for retained offline snapshots/cursors, pending-material survival across restart, assignment-ID replacement, optimistic progress and mistake timestamps, transaction rollback, obsolete metadata removal, an invalidated callback against a closed database, acknowledged edits/reviews racing older responses, and additive migration rollback/data preservation. A complete typed-review UI flow passes after real app initialization; read-only inspection confirms the installed simulator database is at schema 15 with both revision columns. Stored protobuf formats are unchanged. No live-account sync is claimed.
- This is a prerequisite to rejected/ambiguous-review recovery, not its completion. The conflict journal, server-assignment comparison and recovery UI remain next; rejected review batches still stop as documented in the preceding checkpoint.
